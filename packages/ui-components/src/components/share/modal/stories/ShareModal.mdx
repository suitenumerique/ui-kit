# ShareModal

**ShareModal** is the sharing dialog of la Suite: it lets a user search people
and invite them, review and change who already has access, manage pending
invitations, configure the share link, and mass-import contacts from a file.
Every capability is optional and driven by props — you enable the sections you
need and provide callbacks, the modal owns all the UI in between.

Here it is with everything enabled — search for a user (try typing an email),
change a role, open the "..." menu on the members title:

<Canvas of={ShareModalStories.Default} />

## Installation

```tsx
import { ShareModal } from "@gouvfr-lasuite/ui-components";
```

Labels are translated via Cunningham (`useCunningham`), so the modal must live
under a `CunninghamProvider`.

## Basic usage

A minimal sharing dialog: search users, invite them, manage members and
pending invitations, set the share link and copy it. The modal only renders
what you give it: each callback is the place to call your backend, then you
feed the updated lists back through the props.

```tsx
import { useState } from "react";
import {
  AccessData,
  InvitationData,
  ShareModal,
  ShareModalCopyLinkFooter,
  UserData,
} from "@gouvfr-lasuite/ui-components";

type User = UserData<object>;
type Access = AccessData<object, object>;
type Invitation = InvitationData<object, object>;

const ROLES = [
  { label: "Editor", value: "editor" },
  { label: "Reader", value: "reader" },
];

export const ShareDialog = ({
  isOpen,
  onClose,
  shareUrl,
}: {
  isOpen: boolean;
  onClose: () => void;
  shareUrl: string;
}) => {
  const [searchResults, setSearchResults] = useState<User[]>([]);
  const [accesses, setAccesses] = useState<Access[]>([]);
  const [invitations, setInvitations] = useState<Invitation[]>([]);
  const [linkReach, setLinkReach] = useState("restricted");
  const [linkRole, setLinkRole] = useState<"reader" | "editor">("reader");

  return (
    <ShareModal
      isOpen={isOpen}
      onClose={onClose}
      invitationRoles={ROLES}
      // Search: called with the typed query, results come back through
      // searchUsersResult. An empty query means the search was cleared.
      onSearchUsers={async (query) =>
        setSearchResults(query ? await api.searchUsers(query) : [])
      }
      searchUsersResult={searchResults}
      // Invite: users found by the search get an access, unknown emails an
      // invitation (their id is the typed email).
      onInviteUser={async (users, role) => {
        const { accesses, invitations } = await api.share(users, role);
        setAccesses((prev) => [...prev, ...accesses]);
        setInvitations((prev) => [...prev, ...invitations]);
      }}
      // Members
      accesses={accesses}
      onUpdateAccess={async (access, role) => {
        await api.updateAccess(access.id, role);
        setAccesses((prev) =>
          prev.map((a) => (a.id === access.id ? { ...a, role } : a)),
        );
      }}
      onDeleteAccess={async (access) => {
        await api.deleteAccess(access.id);
        setAccesses((prev) => prev.filter((a) => a.id !== access.id));
      }}
      // Pending invitations
      invitations={invitations}
      onUpdateInvitation={async (invitation, role) => {
        await api.updateInvitation(invitation.id, role);
        setInvitations((prev) =>
          prev.map((i) => (i.id === invitation.id ? { ...i, role } : i)),
        );
      }}
      onDeleteInvitation={async (invitation) => {
        await api.deleteInvitation(invitation.id);
        setInvitations((prev) => prev.filter((i) => i.id !== invitation.id));
      }}
      // Share link: who can open it, and with which role.
      linkSettings={true}
      linkReachChoices={[
        { value: "restricted" },
        { value: "authenticated" },
        { value: "public" },
      ]}
      linkReach={linkReach}
      onUpdateLinkReach={setLinkReach}
      showLinkRole={linkReach !== "restricted"}
      linkRoleChoices={[{ value: "reader" }, { value: "editor" }]}
      linkRole={linkRole}
      onUpdateLinkRole={(value) => setLinkRole(value as "reader" | "editor")}
      // Footer below the link settings.
      outsideSearchContent={
        <ShareModalCopyLinkFooter
          onCopyLink={() => navigator.clipboard.writeText(shareUrl)}
          onOk={onClose}
        />
      }
    />
  );
};
```

`api` stands for your own backend calls. `invitationRoles`, `onSearchUsers`
and `onInviteUser` are required as soon as invitations or members are shown
(see "Requirements and validation" below); every other prop is optional and
each section below details one of them.

## Anatomy

From top to bottom the modal shows:

1. **A search input** (`onSearchUsers` / `searchUsersResult`) to find users to
   invite. Hidden when `canUpdate` is `false`.
2. **Pending selection** — users picked from the results stack up with a role
   dropdown (`invitationRoles`) and a share button that fires `onInviteUser`.
3. **Invitations** (`invitations`) — pending invitations, each with a role
   dropdown and a delete action.
4. **Members** (`accesses`) — people who already have access, with role
   management and the optional "Import contacts" menu.
5. **Footer** — link settings (`linkSettings`) and/or your own
   `outsideSearchContent` (e.g. a copy-link button).

## Changing inherited access

With `allowFileImport` and `canRestrict` enabled, the members menu includes
**Restrict access** when `isRestricted` is false. Selecting it opens a
confirmation dialog. Cancel, close, and Escape dismiss it without changing
access; confirming calls `onRestrict` and dismisses the dialog. The consumer
applies the change and updates `isRestricted` on success.

The warning explains that people with access through the parent item will
lose it, while people added directly will keep access. No access count is
required.

When `isRestricted` is true, the menu instead offers **Open access**. Its
confirmation explains that everyone with access to the parent item will
have access to this item, while people added directly keep their access.
Confirming calls `onUnrestrict`; the consumer applies the change and sets
`isRestricted` to false on success. Cancel, close, and Escape make no change.

## Searching and inviting

Type in the search input and the modal calls `onSearchUsers` (debounced by
300 ms); render results by feeding them back through `searchUsersResult`.
Selecting a result adds it to the pending list; the share button then calls
`onInviteUser(users, role)` with the chosen role from `invitationRoles`.

If the query looks like an email address that matches no result, the modal
offers to invite that address directly — useful for people who don't have an
account yet.

```tsx
<ShareModal
  isOpen={isOpen}
  onClose={() => setOpen(false)}
  onSearchUsers={(query) => setSearchQuery(query)}
  searchUsersResult={searchResults}
  invitationRoles={[
    { label: "Admin", value: "administrator" },
    { label: "Reader", value: "reader" },
  ]}
  onInviteUser={(users, role) => invite(users, role)}
/>
```

## Managing members and invitations

Role changes and removals go through `onUpdateAccess` / `onDeleteAccess` and
`onUpdateInvitation` / `onDeleteInvitation`. Per-member role choices can be
computed with `getAccessRoles(access)` (falls back to `invitationRoles`).
Paginate long lists with `hasNextMembers` / `onLoadNextMembers` (and the
invitation equivalents).

Whether a member's access can be deleted is data-driven:

<Markdown>
  {`
| \`is_explicit\` | \`can_delete\` | Deletion allowed |
|---------------|--------------|------------------|
| \`false\` | - | No (implicit access) |
| \`true\`/\`undefined\` | \`false\` | No |
| \`true\`/\`undefined\` | \`true\`/\`undefined\` | Yes |
`}
</Markdown>

For example, to prevent deletion of the last admin:

```tsx
const accesses = rawAccesses.map((access, _, all) => ({
  ...access,
  can_delete: all.length > 1 || access.user.id !== currentUserId,
}));
```

## Importing contacts from a file

With `allowFileImport={true}` (and `canUpdate`), a "..." menu appears on the
members title with an "Import contacts" option. It opens the
[ShareImportModal](?path=/docs/components-share-importmodal--docs), which
parses a two-column CSV/XLSX file (email, role) and hands you the result:

```tsx
const [importModalChildren, setImportModalChildren] = useState<ReactNode>();

<ShareModal
  allowFileImport={true}
  onImportContacts={async (rows) => {
    // rows: { email, role }[]
    try {
      await inviteContacts(rows);
      return true; // closes the import modal
    } catch {
      setImportModalChildren(
        <Alert type={VariantType.ERROR}>Import failed, please try again.</Alert>,
      );
      return false; // keeps it open
    }
  }}
  importModalChildren={importModalChildren}
  onImportFileChange={() => setImportModalChildren(undefined)}
/>;
```

`onImportContacts` is asynchronous: while its promise is pending the import
modal cannot be closed (no ESC, no close button, cancel disabled) and the
import button is disabled with a spinner. Resolve `true` to close the modal;
resolving `false` (or throwing) keeps it open so you can surface the error —
`importModalChildren` renders below the modal content, which is the natural
spot for an error `Alert`. Use `onImportFileChange` to clear it when another
file is selected, so a stale error does not stick to the new attempt.

At most 100 rows can be imported by default; use `maxImportRows` to change the
limit (it is forwarded to the import modal as `maxRows`).

Try it below: download the template from the import modal (or bring any
two-column CSV), import it, and watch the lists refresh — this example mocks a
backend that processes the file, then randomly registers each row

## Read-only and restricted views

Two props control what the viewer may do:

- `canUpdate={false}` — read-only: no search input, no role dropdowns, no
  deletions, no import menu.
- `canView={false}` — the viewer may not even see who has access: the lists are
  replaced with a message (`cannotViewMessage`, `cannotViewChildren`). Note
  that `canUpdate` must also be `false` in that case, otherwise the component
  throws.

## Link settings

Enable the footer with `linkSettings={true}`: a link-reach dropdown
(`linkReachChoices`, `onUpdateLinkReach`) and optionally a link-role dropdown
(`showLinkRole`, `linkRoleChoices`, `onUpdateLinkRole`). Use `hideInvitations`
and `hideMembers` to reduce the modal to the link settings alone:

Without the role selector, only the reach can be changed:

Read-only variants of both are available in the sidebar
(`LinkSettingsOnlyReadOnly`, `LinkSettingsOnlyWithoutRoleReadOnly`), and
`WithoutLinkSettings` shows the opposite: people management with no footer.

### Link expiration

A share link can stop granting access after a given date. Pass the current
expiration with `linkExpiresAt` (`null` when the link never expires) and
handle changes with `onUpdateLinkExpiresAt`:

```tsx
<ShareModal
  linkSettings={true}
  showLinkRole={true}
  linkRoleChoices={[{ value: "reader" }, { value: "editor" }]}
  linkExpiresAt={item.link_expires_at ? new Date(item.link_expires_at) : null}
  onUpdateLinkExpiresAt={(value) =>
    updateLink({ link_expires_at: value?.toISOString() ?? null })
  }
/>
```

When `onUpdateLinkExpiresAt` is provided and `canUpdate` is `true`, the link
role dropdown gets a **Link expires** submenu below the roles:

- **Never** removes the expiration: the callback receives `null`. It is
  checked while the link has no expiration, and selecting it again does not
  call the callback.
- **1 day**, **7 days** and **30 days** set the expiration from today.
- **Choose date** opens a calendar anchored to the dropdown. Past days are
  disabled; **OK** confirms the selected day, **Cancel** or a click outside
  closes it without change.

The callback always receives a `Date` set to the **end of the chosen day**
(23:59:59 in the user's time zone), so the link stays usable during the whole
last day, whatever the time it was set at.

Whenever `linkExpiresAt` is set, the role is displayed with its end date, e.g.
_Reader until Oct 23, 2026_, formatted for the Cunningham locale. This label
also shows in read-only mode, where the submenu is not available. The modal
does not keep the date itself: update `linkExpiresAt` once your backend has
saved the change.

The submenu lives in the link role dropdown, so it requires a visible role
selector (`showLinkRole` with non-empty `linkRoleChoices`).

## Requirements and validation

The component throws at render time when a configuration cannot work:

- `invitationRoles` and `onSearchUsers` are required unless both
  `hideInvitations` and `hideMembers` are set.
- `onInviteUser` is required unless `hideInvitations` is set.
- `canView={false}` requires `canUpdate={false}`.
