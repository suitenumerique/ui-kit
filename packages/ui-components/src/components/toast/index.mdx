# Toast

Cunningham provides a powerful Toast component for displaying any kind of information for a defined amount of time.

<Canvas of={Stories.Demo} sourceState="none" />

## Usage

Toasts are really simple to use, you need to wrap your app inside `CunninghamProvider`.

<Source
  language='tsx'
  dark
  format={false}
  code={`
import { CunninghamProvider } from "@gouvfr-lasuite/ui-components";

const App = () => (

<CunninghamProvider>
  <InnerApp />
</CunninghamProvider>
); `} />

Pass `toastPosition` on `CunninghamProvider` to choose the corner. The toast
slides in from that same side: `bottom-left` (default) arrives from the left,
`bottom-right` sits on the right and arrives from the right.

<Source
  language="tsx"
  dark
  format={false}
  code={`
<CunninghamProvider toastPosition="bottom-right">
  <InnerApp />
</CunninghamProvider>
`}
/>

You can also wrap a subtree in `ToastProvider` with `position`.

And then simply use the `toast` function from `useToastProvider` hook.

<Source
  language='tsx'
  dark
  format={false}
  code={`
const InnerApp = () => {
  const { toast } = useToastProvider();

return (
<button onClick={() => toast("Hello world!")}>
Create toast
</button>
);
};
`}/>

You can also customize the appearance of the toast with the `toast` function. See the API.

<ArgTypes of={toast} />

## Position

`toastPosition` is one of `top-left`, `top-center`, `top-right`, `bottom-left`
(default), `bottom-center`, `bottom-right`. The slide follows the side: a toast
on the right arrives from the right.

## Updating and dismissing

`toast` returns an id you can use to update or dismiss a toast later. `useToastProvider`
exposes `updateToast` and `dismissToast` for that.

<Source
  language='tsx'
  dark
  format={false}
  code={`
const { toast, dismissToast } = useToastProvider();

const id = toast("File moved", VariantType.SUCCESS, {
actions: [{ label: "Cancel", onClick: () => {
undoMove();
dismissToast(id);
}}],
});
`}/>

`updateToast` takes the toast's own props, not the underlying library's options. It
re-renders the toast with them merged over the ones it was raised with, so the wrapper
and everything you leave out are preserved. Pass `message` to replace the text.

<Source
  language='tsx'
  dark
  format={false}
  code={`
const id = toast("Uploading", VariantType.INFO, { progress: 15 });

// Only the progress moves: the message, the variant and the buttons stay.
updateToast(id, { progress: 60 });

// Then switch the whole thing over to the success variant.
updateToast(id, { message: "Uploaded", type: VariantType.SUCCESS, progress: 100 });
`}/>

Passing `duration` to `updateToast` restarts the dismissal timer; leaving it out keeps
the one the toast was raised with.

## Using `Toast` on its own

`toast()` covers the usual case, but `Toast` is exported and can be mounted directly,
for instance to pin a notification inside a page. It then owns its own lifecycle: give
it a `duration` and it dismisses itself after that delay, fading out before calling
`onDelete`. Without a `duration` it simply stays.

<Source
  language="tsx"
  dark
  format={false}
  code={`
<Toast type={VariantType.SUCCESS} duration={6000} onDelete={() => setShown(false)}>
  File moved
</Toast>
`}
/>

Raised through `ToastProvider`, the timer belongs to the provider instead, so it does
not hand `duration` down and the two never compete to remove the same toast. The
component carries `role="alert"` in both cases.

## Shared content with `Alert`

`Toast` and [`Alert`](?path=/docs/components-alert--docs) render their message row
through the same internal component, so the structure and the button placement match.
The props they share are declared once in the exported `NotificationProps` interface,
which both `ToastProps` and `AlertProps` extend: `type`, `icon`, `hideIcon`, `actions`,
`primaryLabel`, `primaryOnClick`, `primaryProps`, `tertiaryLabel`, `tertiaryOnClick`,
`tertiaryProps` and `canClose`.

`ToastProps` adds what only the toast does: `duration`, `progress`, `disableAnimate`,
`onDelete` and `closeToast`. `AlertProps` adds `additional`, `buttons`, `expandable`,
`expanded`, `closed`, `hide`, `className`, `onClose` and `onExpand`.

Both also share the same variant colors. What still differs is the chrome: the toast
floats with an elevation and slides in, the alert sits inline in the page.

## Design tokens

Here a the custom design tokens defined by the Toast.

| Token     | Description           |
| --------- | --------------------- |
| icon-size | Size of the left icon |

The toast now takes its colors and typography from the semantic tokens
(`contextuals.background.surface`, `contextuals.content.semantic.*`) like the rest of the
recent components, so `background-color`, `color` and `font-weight` are no longer read.
Slide durations are handled by the transition, so `slide-in-duration` is no longer
read. `slide-out-duration` still is, for the fade-out of a toast mounted on its own.
