# DropdownMenu

`DropdownMenu` opens a menu of actions or choices from a trigger element. It
follows the [dropdown menu design in Figma](https://www.figma.com/design/hPwxE24MEaX3mBQ0KXNTSY/UI-kit?node-id=11926-1524)
and uses React Aria for the menu button pattern: trigger semantics, focus
management, keyboard navigation, typeahead, selection and submenus.

`ContextMenu` renders its items the same way, and `Filter` and `SearchFilter`
share the row look (`MenuItemBody`).

## Usage

```tsx
import { Button, DropdownMenu } from "@gouvfr-lasuite/ui-components";

<DropdownMenu
  options={[
    { label: "Rename", icon: <Edit />, callback: rename },
    { label: "Share", icon: <Share />, callback: share },
    { type: "separator" },
    { label: "Delete", icon: <Trash />, variant: "danger", callback: remove },
  ]}
>
  <Button variant="tertiary" icon={<More />} aria-label="More actions" />
</DropdownMenu>;
```

Import `@gouvfr-lasuite/ui-components/style` once and use the kit's
`CunninghamProvider` to apply your theme.

The menu manages its open state: there is nothing to toggle. Pass `isOpen` and
`onOpenChange` only to control it, or `defaultOpen` to open it on mount.

## Triggers

The trigger is the single child of `DropdownMenu`. It receives a ref, the
press and keyboard handlers, an `id`, `aria-haspopup`, `aria-expanded` and
`aria-controls`. Any element works as long as it:

- forwards its `ref` and props to a DOM element, as `Button`, native elements
  and `forwardRef` components do;
- is focusable and has an interactive role: a `<button>`, a link, or an element
  with `role="button"` and `tabIndex={0}`;
- has an accessible name, such as visible text or an `aria-label`. The menu is
  named after its trigger.

Components that do not forward their props, such as `UserAvatar`, go inside
a `DropdownMenuTrigger` (see below). A `Tooltip` can wrap the trigger. React
Aria buttons and links are used as they are.

There is nothing to toggle in the trigger's `onClick`: the trigger already
opens the menu. A toggle left over from the previous DropdownMenu is harmless.

A disabled trigger (`disabled`, `aria-disabled` or `isDisabled`, inside a
`Tooltip` too) keeps the menu closed, from the keyboard as well; disabling it
while the menu is open closes the menu. A button trigger never submits the
form it sits in.

### Unstyled trigger

`DropdownMenuTrigger`, also available as `DropdownMenu.Trigger`, is an optional
trigger with no look of its own: wrap any content in it, such as an avatar
with a chevron. It renders a `<button>`, so it is focusable, announced as a
menu button and wired to the menu whatever it contains.

```tsx
import { DropdownMenu, DropdownMenuTrigger } from "@gouvfr-lasuite/ui-components";

<DropdownMenu options={accountActions}>
  <DropdownMenuTrigger className="account-trigger" aria-label="Jeanne Martin's account">
    <UserAvatar fullName="Jeanne Martin" />
    <ChevronDown />
  </DropdownMenuTrigger>
</DropdownMenu>
```

It keeps the font and color of its context and only adds a focus ring. Style
it with `className` (or `style`) and the state attributes:

```scss
.account-trigger {
  gap: 4px;
  border-radius: 999px;

  &[data-hovered] { background-color: var(--c--contextuals--background--semantic--overlay--primary); }
  &[data-pressed] { … }
  &[data-focus-visible] { … }
  &[aria-expanded="true"] { … } // the menu is open
}
```

`className` and `style` also accept a function of the state, as on any React
Aria button: `className={({ isHovered }) => …}`.

Since it is a button:

- give it an `aria-label` when its content has no text of its own: without
  it, the name would be whatever text the content renders, such as the avatar
  initials;
- keep links, buttons and other interactive content out of it.

## Options

| Field | Type | Description |
|---|---|---|
| `label` | `string` | Item name, also used for typeahead |
| `subText` | `string` | Secondary text, announced as the item description |
| `icon` | `ReactNode` | Decorative icon on the left |
| `callback` | `() => void` | Called when the item is picked |
| `value` | `string` | Makes the item selectable, see [Selection](#selection) |
| `isChecked` | `boolean` | Makes the item selectable and sets its checked state |
| `isDisabled` | `boolean` | Keeps the item visible, skips it in keyboard navigation |
| `isHidden` | `boolean` | Removes the item, along with the separators it leaves orphaned |
| `variant` | `"default" \| "danger"` | `danger` for destructive actions |
| `keepOpen` | `boolean` | Keeps the menu open after the item is picked |
| `children` | `options` | Entries of a submenu |
| `href`, `target`, `rel` | `string` | Renders the item as a link |
| `shortcut` | `string` | Keyboard shortcut displayed at the end of the row |
| `opensInNewWindow` | `boolean` | Appends "(new window)" to the accessible name |
| `testId` | `string` | `data-testid` of the item |
| `id` | `string` | Unique key; defaults to `value`, then `label` |
| `showSeparator` | `boolean` | Deprecated: use a `{ type: "separator" }` entry |

## Selection

Items with a `value` or an `isChecked` flag are selectable. They are checked
when `isChecked` is true or their `value` is in `selectedValues`, and picking one
calls `onSelectValue` with its value, then its `callback`.

Selectable items are exposed as radio items (`selectionMode="single"`, the
default) or checkbox items (`"multiple"`) with their checked state, so screen
readers announce it. Other items stay plain menu items. A multiple selection
menu stays open while items are toggled.

## Submenus

Give an option `children` to open a submenu from it. Submenus open on hover,
with the right arrow, Enter or Space, and close with the left arrow. They
inherit the menu variant and flip to the other side when there is no room.

<Canvas of={DropdownMenuStories.WithSubmenus} />

## Messages

`topMessage` and `bottomMessage` display text above or below the items. They
are the description of the menu, read by screen readers when it opens. Keep
them free of interactive content: focus stays on the items.

## Size

The menu takes the width of its items, between 150px and 320px (the
`min-width` and `max-width` tokens). Beyond the maximum, labels and descriptions
wrap onto several lines instead of widening the menu. Long menus scroll, with a
fade on the edge that still has content.

## Composition

For content the `options` array cannot describe, such as titled sections, use
the parts `DropdownMenu` is built from. `DropdownMenu.Root` takes the
trigger and a `DropdownMenu.Popover`, which takes `DropdownMenu.Item`,
`DropdownMenu.Section`, `DropdownMenu.Separator` and `DropdownMenu.Submenu`.
They accept the React Aria props of `MenuTrigger`, `Menu`, `MenuItem` and
`MenuSection`, such as `selectionMode`, `selectedKeys` and `onAction`.

```tsx
<DropdownMenu.Root>
  <Button>Account</Button>
  <DropdownMenu.Popover>
    <DropdownMenu.Section title="Account">
      <DropdownMenu.Item icon={<User />} description="Name, email and avatar">
        Profile
      </DropdownMenu.Item>
    </DropdownMenu.Section>
    <DropdownMenu.Separator />
    <DropdownMenu.Item variant="danger" onAction={logout}>
      Log out
    </DropdownMenu.Item>
  </DropdownMenu.Popover>
</DropdownMenu.Root>
```

## Keyboard and accessibility

- Enter, Space or the down arrow opens the menu on its first item; the up arrow
  opens it on its last item. With `trigger="longPress"`, use Alt + down arrow.
- Up and down arrows move between items and wrap. Home and End jump to the
  first and last items. Typing a label moves to the matching item.
- Disabled items are announced but skipped by the arrows.
- Enter or Space picks the focused item. Escape closes the current menu: in a
  submenu, focus returns to its item. Tab and Shift + Tab close the whole
  menu, submenus included, and focus returns to the trigger.
- While the menu is open, the rest of the page is hidden from assistive
  technologies and a click outside only closes the menu.
- The trigger exposes `aria-haspopup` and `aria-expanded`; the menu is named
  after the trigger and described by its messages.
- Item descriptions and shortcuts are announced; icons are hidden.
- The focused item is highlighted with the hover background, by keyboard as
  by pointer. In forced-colors mode, it gets a system-colored outline and
  separators stay visible.

## Theming

The menu reads the `dropdown-menu` component tokens: surface colors, border,
radius, shadow, widths, item spacing, sizes, colors and the tiny variant
sizes. Override them in your Cunningham configuration, under
`components["dropdown-menu"]`.

## Migration from the previous DropdownMenu

The `DropdownMenu` was rebuilt on the React Aria menu button pattern. Its
props, `options` and types keep their names and shapes; these changes may need
an update in your code:

| Before | Now |
|---|---|
| `children` wrapped in a `div`, any content | `children` is the trigger element itself (see [Triggers](#triggers)) |
| `isOpen` required to open, toggled in the trigger `onClick` | The menu opens by itself; `isOpen` / `onOpenChange` stay available to control it. A leftover `onClick` toggle is harmless |
| Checked items announced as plain menu items | Items with a `value` or `isChecked` are `menuitemradio` / `menuitemcheckbox` with `aria-checked`: tests using `getByRole("menuitem")` on them need the new role |
| Row markup `__label-container`, `__label-subtext` | `__content`, `__description` (`MenuItemBody` renders the new markup) |
| `topMessage` / `bottomMessage` outside the menu | Same props, now the description of the menu |
| Tab kept focus in the menu | Tab closes the menu |
| Arrow keys and clicks in the menu reached the trigger's ancestors | They stop at the menu |

Remove the `onClick` toggle and the `useDropdownMenu` state when you do not
need to control the menu, and give icon-only triggers an `aria-label`.
